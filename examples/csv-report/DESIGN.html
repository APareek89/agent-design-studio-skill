Brief and scope

The brief as given, and how this design reads it. Facts the brief did not give are assumptions with owners.

Brief (verbatim)
Design a small daily report that joins two CSV files by order ID. One has promised-delivery timestamps and the other actual-delivery timestamps, both ISO UTC. Flag delivered orders more than 24 hours late and export a CSV for the operations team. No emails, remote updates, forecasting or conversational interface.
FieldDesign reading
Scope First releaseThe tool writes a local CSV. It does not send messages, forecast delays or change any order.
CTX1 Business decision and actorsOperations uses the exported daily CSV to identify which delivered orders exceeded their promised delivery timestamp by strictly more than 24 hours. The tool reports facts; it does not decide compensation, contact customers or change orders. Proposed owner roles are not named people or confirmed appointments.
CTX2 Trigger, scope and completionA manual CLI or existing local scheduler invokes one local batch run with two CSV paths and optional report date. Default is the previous UTC date. Join uses exact order_id equality; no normalization or fuzzy match. Success means one durable date directory with report.csv and a checksum-verified COMPLETE manifest. A valid empty day produces a header-only CSV. Non-goals: emails, messaging, remote updates, forecasting, chat UI, LLMs, customer actions and automatic correction of prior reports.
CTX3 Date and data rulesValidate entire snapshots before filtering. Blank actual timestamps are undelivered and excluded. A delivered actual ID with no promised row fails the run, even outside the report window; promised-only rows are counted as undelivered/not matched. Duplicate IDs in either file fail the entire run even if rows are identical. Only actual rows within [D 00:00:00Z,(D+1) 00:00:00Z) are reported. Signed lateness uses exact integer microseconds: flag iff actual-promised > 86400000000. Actual before promised is valid and not late. Empty values, bad headers/CSV/UTF-8, duplicate header names, invalid timestamps, non-UTC values and unsafe IDs block publication.
CTX4 Output and local authorityCSV columns in order: order_id,promised_delivery_utc,actual_delivery_utc,lateness_seconds,is_more_than_24h_late. Sort by case-sensitive ASCII order_id, preserve leading zeros, normalize timestamps to UTC Z with six fractional digits, emit signed decimal seconds with exactly six decimals and lowercase true/false. UTF-8 without BOM, CRLF records, standard CSV escaping. Local manifest includes schema_version, report_date, config_digest, input SHA-256 hashes, row counts, excluded-undelivered/out-of-window counts, report SHA-256, status COMPLETE and run_key. No raw rows in logs. This design exercise writes only design artifacts; running or scheduling the business report is separate implementation work. Manifest is exactly {schema_version:string="delivery-report-v1",report_date:YYYY-MM-DD,config_digest:hex64,promised_sha256:hex64,actual_sha256:hex64,raw_count_promised:int>=0,raw_count_actual:int>=0,rows:int>=0,flagged_rows:int>=0,excluded_undelivered:int>=0,excluded_out_of_window:int>=0,promised_only_rows:int>=0,report_sha256:hex64,status:string="COMPLETE",run_key:hex64}; no timestamp or absolute path is included in this deterministic object. Serialize manifest JSON with sorted keys and compact separators in UTF-8 followed by one LF. config_digest = SHA256 of compact sorted-key UTF-8 JSON with exactly {schema_version,threshold_microseconds,max_rows,max_bytes_per_file,deadline_seconds}; parser/ID/output contracts are versioned by schema_version; allowlisted paths are deployment capabilities, excluded from digest. run_key = SHA256 of compact sorted-key UTF-8 JSON with exactly {schema_version,report_date,config_digest,promised_sha256,actual_sha256}. No LF in either hashed JSON input. Fields use the typed values in C1/C2/C3, not stringified numbers.
CTX5 Quality and value measurementsR1 defines daily record accuracy, publication completeness and operations review-time KPIs. Baselines are unknown. Hypothesis: exact deterministic fixtures pass 100%; all published files have valid manifests; reviewer effort decreases without any missed/extra flagged rows. Actual business impact requires future shadow/manual comparison and the R5 experiment; no savings or production accuracy is claimed.

C1 Run controller and immutable read
CLI run --promised PATH --actual PATH [--report-date D] --out ROOT. Reject future/current day; fail rather than use partial reads. Before and after reading verify same inode/size/mtime_ns; change gives INPUT_IO. Hash exact bytes in memory. Lock mkdir is exclusive; never break an existing lock automatically. SHA256 run_key is hash of compact sorted-key UTF-8 JSON {schema_version,report_date,config_digest,promised_sha256,actual_sha256}; canonical JSON has no spaces. config_digest hashes parser/limits/output/threshold settings, excluding absolute paths. Cancellation checked at bounded row batches and immediately before publication; lock metadata contains pid, start time and run key when known. Whole-run deadline 120s; no read retries. Exact digest key sets/serialization are CTX4; schema_version versions all parser/ID/output behavior. config_digest excludes allowlisted paths and includes only schema_version,threshold_microseconds,max_rows,max_bytes_per_file,deadline_seconds with native JSON numeric types.
Why code: Dates, hashes, identity and locks are exact deterministic operations; no natural-language interpretation is needed.
Authority: Operator-configured local filesystem permission only; no runtime approval conversation. Recheck local path/capability before reads/writes. No external action is authorized by this design.

C4 Atomic local publisher Code: write tool
Final directory ROOT/YYYY-MM-DD contains report.csv and manifest.json. Under acquired per-date lock, existing COMPLETE manifest with same run_key and matching CSV hash => ALREADY_COMPLETE; any differing or incomplete final directory => CONFLICT. Stage at ROOT/.staging-<date>-<run_key>-<pid>-a<retry_count>; create files exclusively, fsync each and directory. Manifest schema is in CTX4; input counts are C2/C3 outputs. Recheck output-root permission and lock ownership before rename. Publish by same-filesystem directory rename then fsync output root; any exception after rename begins => UNKNOWN and C5 reconciliation, never immediate retry. Before rename, cancellation deletes staging and returns CANCELLED; failures known before rename return NOT_COMMITTED. After rename begins defer cancellation until reconciliation determines whether published. Stage no later than deadline; uncertain timeout is UNKNOWN. No network, input mutation or automatic overwrite. The exact typed manifest/canonical JSON is CTX4. Before ALREADY_COMPLETE verify all stored date/schema/config/input hashes and derived counts against the current expected manifest, plus actual report hash; any discrepancy is CONFLICT. A retry uses its fresh -a1 directory; best-effort remove the owned prior -a0 stage after ABSENT proof, but cleanup failure never authorizes reading/reusing that stage. No automatic deletion of another run stage. Any cancellation signal received after rename begins makes C4 return UNKNOWN, even if rename appears successful, so W6 proves COMMITTED or ABSENT before selecting terminal; no post-start CANCELLED outcome bypasses readback.
Why code: Atomic publication with content identity prevents partial reports, duplicate runs and false completion.
Authority: Operator-configured local filesystem permission only; no runtime approval conversation. Recheck local path/capability before reads/writes. No external action is authorized by this design.
