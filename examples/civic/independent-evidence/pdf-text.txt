Streetlight repair intake and operator-assisted routing
The system in one sentence
Help city staff route streetlight reports and track each saved ticket.

Key design calls
Staff approve ticket changes. Rejected: Free agent writes. Why: People own routing
Reuse known tickets. Rejected: New ticket each time. Why: Avoid double work
No equipment control. Rejected: Remote switching. Why: Keep the first release safe

Plain words and scope
Staff can create or link a repair ticket. The system cannot switch lights or control street equipment.
A fingerprint is a check that the approved details have not changed. A record ID is proof from a tool that the change was saved.

Architecture and model budget

F1 - Pattern and boundary
Choice: Choose a durable code workflow with one bounded classification LLM and operator confirmation. Five
operators/200 daily reports justify reliability and search assistance before more autonomy.
Rejected: Rejected autonomous multi-agent dispatch: unnecessary authority, harder replay and more calls.; Code-only rules remain
fallback and comparison: reliable known categories...
Trade-off: One model call handles judgement; code owns policy and effects. Replace LLM with code-only if held-out routing gains do not
justify cost/latency.

F2 - State and ownership
Choice: Choose transactional relational case/plan/approval/outbox journal with persisted timer jobs, W1-W11 and
CAS versions. Authoritative city ticket system owns actual tickets; local store owns proposals, approvals and...
Rejected: Rejected in-memory chat chain: loses human waits and unknown-commit ownership.
Trade-off: Simple deploy footprint but requires robust timer worker, backups, recovery drills and adapter proof. Search snapshots are never
authoritative for commit.

F3 - Orchestration comparison
Choice: Choose a small code state machine + relational job queue initially. Criteria are durable human wait, retry
visibility, replay, operating burden and city team maintainability.
Rejected: Candidate durable workflow engine: investigate managed or open-source workflow engine if timer/recovery load outgrows SQL
queue; verify actual product capabilities...
Trade-off: Code queue: fewer moving parts, recovery logic owned by IT. Workflow engine: evaluate durable timers/replay on same fixtures
and operating burden in...

F4 - Tool permissions and equipment exclusion
Choice: Allow C2 city data reads; C6 only create-ticket/attach-report; C7 operation reads; C1/C4/C5/C8 local case
writes. Deny arbitrary URLs, shell/tools from model, direct equipment endpoints, ticket closure...
Rejected: Rejected broad municipal administrator token for integration convenience.
Trade-off: Adapter-side and egress policy controls are required. Prove attempted equipment action rejected before any network call.
Credentials held server-side secret store, rotated...
Access: Separate context-read, ticket-create/attach and operation-read identities; no shared broad admin or equipment credential.

F5 - Data minimization and platform options
Choice: Prefer city-managed relational database, encrypted object store for restricted original reports, indexed
city-scoped asset/ticket snapshots, and city identity/secret infrastructure already supported by IT. Unverified
candidates only...
Rejected: Rejected global vector index mixing cities and raw personal details.; Candidate semantic index only for candidate search; no
authority to...
Trade-off: Relational ledger gives transaction/version ownership; object storage for restricted originals separates access. Hosting options
below use same categories - case ledger, restricted...
Access: Separate context-read, ticket-create/attach and operation-read identities; no shared broad admin or equipment credential.
These are reader summaries. Complete choices, alternatives, gates and owners are in PRD.md and design.json.

R2 - Safety, ownership and privacy guardrails

Signals: Urgent recall affects time to staffed assessment, not a proven reduction in harm.; Readback/receipt completeness prevents false
dispatch claims.; Queue ownership is service continuity...
